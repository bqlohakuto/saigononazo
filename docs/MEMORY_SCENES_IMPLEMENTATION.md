# 回想素材の実装と立ち絵の継続表示

2026-10-20。第2の補完〜第7の素材を実装し、ユーザーの変更指示により、第1を含む回想の立ち絵をト書きでも保つ。

`memory-visuals.js` は元LOG IDから場面と人物の在不在を決定する。文章のページ数や発話者が変わっても、同じ会話中なら画像が消えない。第2〜第7の627件の元ID、40場面と素材の対応は `MEMORY_SCENES_IMPLEMENTATION.json` に記録する。

第3の通話中や登場前、彼女がバスへ乗った後、時間・場所の切替と回想終了は背景のみへ切り替える。第5の実際の本文ID、着信音・鼻歌・信号音の独立IDも扱う。食卓・机には座り姿と手前の天板を置き、ソファ・キッチンは家具の輪郭で重ねる。

生成した新規24画像と既存制作の第3の3画像を使用。原画の描き直し・減色・切り貼りはせず、表示層だけで配置する。背景は細かいドット調、人物は第1原画の細線を引き継ぐ。通常のハナの立ち絵、台詞、元LOG ID、謎・解答、セーブ形式は変更しない。

## 検証

- 回想・会話・キャッシュ更新の25試験が合格。627件のIDとページ分割したIDが存在する素材に対応することを検査。
- ChromiumのPC・スマホ横画面で、第1の実際のピアノ正解から回想、本編復帰、セーブ再開、LOG・会話枠の非表示/復帰を確認。
- 第2〜第7の実装台詞を使って、ト書きの継続表示、座り姿と家具、重要カット、会話枠、回想終了時の解除を確認。
- 全単体試験は変更前117件中17件失敗、変更後119件中16件失敗。今回の変更による新規失敗はなし（キャッシュの版番号不一致を解消）。既存の別機能の失敗は対象外として残す。
