# 第2〜第8：ピクセル素材統一・作業範囲（2026-10-12）

## 基準と制約

- **画風の基準**：ハナ `images/characters/hana-current/`、携帯 `images/items/phone-open-frame.png`、第1の `room01_*_fine.png`、オープニング `white-room-fine.png`。細かなピクセル輪郭・階調を合わせる。
- **描き替えるのはビジュアルのみ**。確定台詞、LOG ID、謎の答え、調査順序、アイテム、部屋遷移は変更しない。
- **PC優先／横向きスマホ対応**。16:9程度の広いゲーム領域を主基準とし、低い画面でも調査・会話操作を隠さない。
- **先に重複確認**。すでにCSS・SVG・別レイヤーで表示しているオブジェクトを背景画像に二重に描かない。クリック範囲と絵を同じ座標系で扱う。
- 正式な絵を新規制作する場合は、`docs/IMAGE_ASSET_LIST.md` の従来ルールどおり、1枚ずつ確認・採用後に本実装。未確定情報や謎の解答を絵に書き加えない。

### 扉デザインの追加決定（2026-10-12）

第2の扉は第1の採用済み正面背景 `images/background/room01/pixel/room01_front_fine.png` 内の**同じ木製扉**を使う。異なる木目・取っ手・パネルの新規扉は作らない。扉と背景は別レイヤーで扱い、CSSの仮扉や背景への焼き込みによる二重表示を避ける（詳細は `docs/ROOM02_PIXEL_DRAFT.md`）。

## 実装に進む順序

1. 第2の**現行画面をPCと横向きスマホで確認**し、現存する扉・机・ブロックの形状と座標を記録する。
2. 第2の**背景1枚のラフ／完成案**を作り、既存CSS描画とどちらを残すか選ぶ。採用前は本編へ差し替えない。
3. 第2の操作オブジェクトを別レイヤーへ統合し、**ボタン当たり判定・5桁の謎・進行テストを維持**する。
4. 第3→第4の順に同じ制作手順を適用する。
5. 第5〜第8は `docs/PLAYTEST_CURRENT_GAPS.md` の未確定要素を確定素材として扱わず、先に舞台構図と画面設計だけを固める。

## 公開表示の継続検証

- `tests/public-opening.browser.cjs` と `.github/workflows/public-opening-visual.yml` が、GitHub Pages実画面をPC Chromiumと横向きWebKitで確認する。
- 背景PNGのHTTP取得／画像としてのデコード、ハナ登場、扉の表示と開閉、白転、第1の背景を検証し、各節目のスクリーンショットをActions artifactへ保存。
- 実機iPhoneやAndroidではないため、タッチ操作・Safari固有の振る舞いは必要に応じて実機でも検証する。
- `game-flow.test.cjs` の既存3失敗は今回のピクセル素材の範囲外。テスト側を無条件に修正したり、ゲームの確定仕様を変更して通したりしない。
