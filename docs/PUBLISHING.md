# 公開・投稿仕様

『最後の謎が解けるまで』完成後の公開先と、投稿しやすい状態を維持するための実装方針をまとめる。

## 公開方針

- **GitHub**：開発・ソース管理用
- **itch.io**：正式公開先の候補
- **PLiCy**：国内向け公開先の候補
- ゲーム本体は **HTML / CSS / JavaScript で動作するブラウザゲーム**として完成させる。
- PCだけでなく、現在の方針どおり **スマートフォンでのプレイを優先**する。

## 投稿サイト対応のための実装ルール

1. ゲームの起点は `index.html` とする。
2. 画像・音声・CSS・JavaScriptなどの参照は、原則として **相対パス**を使用する。
3. 特定のローカル環境やGitHub上のURLに依存しない構成にする。
4. 静的Webサイトとして動作できる状態を維持する。
5. タップ操作を前提にし、PCではクリックでも同じ操作ができるようにする。
6. 画面サイズが変わっても主要UI・会話・謎解きが破綻しないようレスポンシブ対応を維持する。
7. iPhone / Safariを主要確認環境のひとつとする。
8. 投稿用パッケージは、ゲーム実行に必要なファイルだけをまとめたZIPを作れる構成にする。
9. 開発用ドキュメント、試作ページ、不要素材などは、投稿用ZIPから除外できるようにする。

## セーブデータ

- ブラウザ版のセーブ機能は、現在のWebゲーム向け方式を基本とする。
- 公開サイトごとに保存領域が分かれる可能性があるため、GitHub版・itch.io版・PLiCy版でセーブデータを共有することは前提にしない。
- セーブ形式を変更する場合は、可能な範囲で旧セーブとの互換性を考慮する。
- 詳細は `docs/SAVE_FORMAT.md` を参照する。

## 完成時の投稿用パッケージ

投稿用ZIPのルートに `index.html` が存在し、そこから必要なファイルをすべて読み込める状態にする。

想定例：

```text
release/
├─ index.html
├─ *.js
├─ *.css
├─ images/
├─ audio/
└─ fonts/
```

実際のフォルダ構成は開発状況に合わせて変更してよいが、投稿先ごとに大きなコード変更をしなくても公開できる状態を目標とする。

## 公開前チェック

完成時は最低限、以下を確認する。

- タイトルからエンディングまで通してプレイできる
- 「はじめる」「つづきから」「設定」「作者コメント」が正常に動作する
- セーブ／ロードが正常に動作する
- PC操作とスマホ操作の両方で進行不能にならない
- iPhone / Safariで表示・タップ・音声再生を確認する
- 画面回転や画面サイズ差で重要UIが隠れない
- 画像・音声などの404がない
- 外部URLや開発環境に依存した参照が残っていない
- 投稿用ZIP単体でゲームが動作する
- ネタバレになる開発用ファイルを投稿パッケージへ含めない

## 投稿ページ用に準備するもの

ゲーム完成後、投稿先向けに以下を用意する。

- タイトル
- ゲーム紹介文
- ジャンル
- 操作方法
- プレイ時間の目安
- 対応端末／推奨ブラウザ
- 注意事項
- クレジット
- バージョン表記
- タイトル画像
- サムネイル
- スクリーンショット

## 運用イメージ

開発はGitHubの `main` を基準に進める。

公開時は `main` から投稿に必要なファイルだけを抽出してリリース用ZIPを作成し、itch.io / PLiCyへアップロードする。

そのため、今後の実装では「GitHub上で動けばよい」ではなく、**一般的な静的Webゲームとして単独配布できること**を維持する。
